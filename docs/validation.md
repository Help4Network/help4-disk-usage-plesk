## Automated

Native package regressions use isolated synthetic source trees, not live installation directories. They prove exact public payload bytes/modes/timestamps, included license equality and deterministic archive/checksum output; reject accidental private files, missing workers/Windows helpers/license, source/metadata/file/ignored-bytecode links, Windows reparse points/junctions, nonregular objects and unsafe/duplicate module metadata; and preserve the prior ZIP/checksum on validation rejection. Simulated root/child reparse controls reject before traversal, missing Windows metadata fails closed, and real root/child junction fixtures run on Windows. Normal bytecode remains excluded. The POSIX FIFO fixture skips explicitly on Windows; native junctions skip explicitly elsewhere, and symlink cases skip if the runner identity cannot create them. Inspect exact-head CI and skips rather than call these native Plesk install, path-race or filesystem-failure transaction proof.

Linux: no-follow, replaced-directory identity, hidden/Unicode names, raw-byte filename partial report (including PHP decoding when installed), sparse logical bytes, stale age, entry/directory bounds, no absolute-path output. Windows: actual Win32 handles, handle-bound enumeration, junction rejection, post-check FSCTL reparse mutation, pre-opened writer rejection, pinned-ancestor rename denial, UNC/device/ADS/root rejection. Windows tests must run on Windows, not just skip on Linux. PHP: access denial, originating admin decision and fresh role recheck, traversal rejection, cached membership, correct parent jump, export stripping and formula neutralization; service-plan precedence/hard bounds, actor/subscription/server admission, queue lease/expiry, policy changes, transfer/token isolation and failure retention; release metadata validation, admin/impersonation isolation, cooldown and failed-check cache preservation. PHP tests run on both OSes; fixture success is not native SDK proof.

## Native Matrix: Both Linux And Windows

Windows ACL automated tests cover raw descriptors (including deny/allow combinations, null DACLs, unsupported ACEs and inherited grants), real private-file and executable ACLs, ancestor replacement grants, junctions, safe-path rejection and limits on Windows runners under PowerShell 5.1 and 7. Final-operation controls replace only the elapsed clock after genuine object metadata inspection: below-deadline/exact-object-limit success, equal/above-deadline rejection and one-fewer-object-limit rejection are deterministic, without sleeps. PHP tests reject malformed/nonzero/overbroad diagnostic responses. The [operator diagnostic](windows-acl.md) is a read-only snapshot, not native installer verification, continuous enforcement or complete Python dependency validation.

Actual-source-body simulated Windows fixtures additionally reject worker/bridge/health/administrator-diagnostic execution when the captured runtime fails its ACL preflight, including a changed policy between reads, and retain legitimate-execution controls. The diagnostic fixtures also retain Linux behavior without a Windows ACL dependency and check generic runtime failure output. These are independent of the PowerShell ACL tests: they prove PHP ordering/binding, not Windows hosting-user effective access. Both tests and native Plesk verification are required.

WHMCS guard/report fixtures reject foreign/inactive services before IO, bind current client/server/subscription/owner/home/mapping identities and reread scope after IO. The installable candidate adds SDK/transport/SQLite tests for activation, exact mappings, TLS options/XML/nonce/pin/response caps, selected-client/transfer changes, role/permission denial, disconnect tombstones, leases/rate caps and escaped pages. Health preserves unknown/stale counters and 20-server bounds; actual Linux/Windows collectors interoperate with strict metadata exports. Lifecycle fixtures exercise active scanner/RPC/pending uninstall guards and private locks. These are not licensed native API authentication, true TLS network, MySQL concurrency, WHMCS framework or Plesk File Manager proof; see [acceptance runbook](whmcs.md).

`php tests/whmcs_health.php` adds 131 cached-dashboard controls using genuine SQLite reads and a post-query fixture hook. Current-role/access revocation, disabled/logout/masquerading administrators and a switch to another authorized administrator reject the final page after private state IO. Malformed JSON/oversized state/invalid or null pins/invalid endpoints produce only an unavailable row with null measurements, preserving a valid neighboring observation; disabled precedence, restored configuration, unpinned cache rejection, strict availability flags, pagination and zero outbound collection remain verified. These are framework/database fixtures, not native WHMCS session semantics, MySQL concurrency, TLS authentication or an atomic/continuous configuration snapshot.

`php tests/queue_lock.php` holds the real shared state lock in a separate process, proves rejection at its two-second contention deadline without callback/state mutation or stream leaks, then verifies acquisition after a brief holder release and recovery after a callback exception. Clock-backed unchanged-source controls additionally reject retries after expiry, late successful acquisition and noncontention lock errors while retaining legitimate return and cleanup controls. A five-second parent watchdog rejects the preceding unbounded implementation. Linux/Windows PHP CI exercises OS lock behavior; neither these tests nor the polling deadline certify native Plesk concurrency, network filesystems or uninterruptible filesystem calls.

## Remaining 1.0 Gates

Implemented in source with fixture tests: native service-plan hook/policy mapping, queue expiry/failure/identity protections and administrator release-discovery UI. Native role/synchronization/network/upgrade validation remains required.

Scheduled stale-cache rotation is now implemented in source and fixture-tested, opt-in and subject to existing caps. The isolated Linux container's SDK readback confirms one registered module rotator with scheduling disabled. This is not working background execution. Native execution, full idempotent upgrade/removal, active-worker uninstall guards and large-fleet inventory-query bounds still need native verification. No unattended installer is included.

`php tests/scheduler_deadline.php` runs the existing policy/rotation suites, then exercises the unchanged scheduler body with genuine private queue state and deterministic post-operation clocks. Its 224 controls cover claim, inventory, final report lookup, subscription relookup, reservation, task setup, manager construction and accepted-task return below/equal/above the ten-second monotonic deadline, plus failed starts. Expired work cannot begin a new task; late reservations release only their token and retain the consumed rate attempt. A task already accepted by Plesk retains its live reservation. Completion markers and stream cleanup remain intact. These SDK fixtures cannot interrupt a native database/filesystem/task call, certify native concurrency or prove a bounded inventory query.

Still open: native Windows/Linux panel QA, Windows ACL installer verification, native WHMCS connection/deployment/freshness, independent post-fix security review and final version-matched native tutorials. Pending features must not be advertised as available. See [platform matrix](platform-support.md).

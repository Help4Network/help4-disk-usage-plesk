# Validation And 1.0 Release Gates

0.3.0 is a development preview. Record environment/date for each check. CI is not live Plesk proof.

## Automated

Native package regressions use isolated synthetic source trees, not live installation directories. They prove exact public payload bytes/modes/timestamps, included license equality and deterministic archive/checksum output; reject accidental private files, missing workers/Windows helpers/license, source/metadata/file/ignored-bytecode links, Windows reparse points/junctions, nonregular objects and unsafe/duplicate module metadata; and preserve the prior ZIP/checksum on validation rejection. Simulated root/child reparse controls reject before traversal, missing Windows metadata fails closed, and real root/child junction fixtures run on Windows. Normal bytecode remains excluded. The POSIX FIFO fixture skips explicitly on Windows; native junctions skip explicitly elsewhere, and symlink cases skip if the runner identity cannot create them. Inspect exact-head CI and skips rather than call these native Plesk install, path-race or filesystem-failure transaction proof.

Linux: no-follow, replaced-directory identity, hidden/Unicode names, raw-byte filename partial report (including PHP decoding when installed), sparse logical bytes, stale age, entry/directory bounds, no absolute-path output. Windows: actual Win32 handles, handle-bound enumeration, junction rejection, post-check FSCTL reparse mutation, pre-opened writer rejection, pinned-ancestor rename denial, UNC/device/ADS/root rejection. Windows tests must run on Windows, not just skip on Linux. PHP: access denial, originating admin decision and fresh role recheck, traversal rejection, cached membership, correct parent jump, export stripping and formula neutralization; service-plan precedence/hard bounds, actor/subscription/server admission, queue lease/expiry, policy changes, transfer/token isolation and failure retention; release metadata validation, admin/impersonation isolation, cooldown and failed-check cache preservation. PHP tests run on both OSes; fixture success is not native SDK proof.

## Native Matrix: Both Linux And Windows

`php tests/runtime_response.php` executes the unchanged PHP runtime-check body with simulated Linux/Windows and unsupported-host constants and a supplied subprocess fixture. It requires the captured executable/isolated command/five-second/16 KiB limits, a typed Python version tuple matching the collector's minimum, empty error list, explicit false native-panel/private-storage validation flags and credit; malformed or incomplete responses refuse and unknown fields are stripped. Unsupported hosts refuse before executable/context/transport access. This does not authenticate an executable or prove its APIs, ACLs, TLS, native installation or continuous enforcement. Linux/Windows `tests/runtime.php` retains real interpreter/probe rejection; macOS explicitly records that native transport cases are not executed, while the simulated response controls and separate real subprocess suite still run.

`php tests/process_deadline.php` evaluates the unchanged subprocess-runner body with deterministic monotonic clocks, synthetic process resources and genuine private output files. Below/equal/above-deadline controls cover temporary/private preparation, launch, status/metadata polling, sleeps and final reads; an expired preparation cannot launch, running-child refusal requests direct termination, and completed captures retain literal arguments, exit status and cleanup. Invalid limits reject before clock/storage/launch. These control-flow fixtures complement `php tests/process.php`, which launches real Python children and verifies output caps, timeout, ignored termination and cleanup. They do not prove native Plesk runtime/Windows hosting-user access, interruptibility of filesystem/process calls or a hard wall-clock bound on process termination/cleanup.

Windows ACL automated tests cover raw descriptors (including deny/allow combinations, null DACLs, unsupported ACEs and inherited grants), real private-file and executable ACLs, ancestor replacement grants, junctions, safe-path rejection and limits on Windows runners under PowerShell 5.1 and 7. Final-operation controls replace only the elapsed clock after genuine object metadata inspection: below-deadline/exact-object-limit success, equal/above-deadline rejection and one-fewer-object-limit rejection are deterministic, without sleeps. PHP tests reject malformed/nonzero/overbroad diagnostic responses. `php tests/permissions_response.php` executes the unchanged PHP preflight body with simulated 32/64-bit Windows filesystem/environment and bounded transport fixtures: exact System32/Sysnative selection, command arguments and captured executable binding, one policy read only on fallback, response types/required fields/object bounds, unknown-field stripping and early malformed-root/missing-shell rejection without transport. It does not invoke PowerShell or modify ACLs; native Plesk shell/environment and hosting-user effective-access tests remain required. The [operator diagnostic](windows-acl.md) is a read-only snapshot, not native installer verification, continuous enforcement or complete Python dependency validation.

Actual-source-body simulated Windows fixtures additionally reject worker/bridge/health/administrator-diagnostic execution when the captured runtime fails its ACL preflight, including a changed policy between reads, and retain legitimate-execution controls. The diagnostic fixtures also retain Linux behavior without a Windows ACL dependency and check generic runtime failure output. These are independent of the PowerShell ACL tests: they prove PHP ordering/binding, not Windows hosting-user effective access. Both tests and native Plesk verification are required.

`php tests/settings.php` executes unchanged Linux/Windows settings-controller and private-store bodies with SDK/ACL/runtime fixtures and genuine private file reads and OS write locks. It rejects original-administrator demotion, impersonation, logout or switches after policy reads, Windows preflight, runtime probes and lock acquisition; passive GET also rejects access loss just before returning. Refusals preserve policy/scan/rate/bridge/rotation state and remove private policy data from the view. Same-ID SDK object replacement, generic diagnostic failure, numeric identity validation (including stable zero), captured-runtime preflight, POST-303 and lock recovery retain controls. These are SDK control-flow fixtures, not native Plesk session reload semantics, database revocation latency, effective Windows ACLs or continuously atomic authorization between a final check and a write/render.

`php tests/domain_viewer.php` executes the unchanged access-library body with synthetic SDK inventory/session fixtures. Subscription enumeration binds the original numeric client ID, administrator flag and impersonation state from one client object, rejects changes after inventory or permission filtering, and uses the original administrator decision instead of mixing a current session with an earlier client. Stable authorized administrator and permission-filtered non-administrator/impersonated views, same-ID SDK object replacement, empty sets and zero-valued IDs remain controlled. Malformed identities/flags fail before inventory. This is snapshot/control-flow protection, not native session/database permission reload, continuously atomic entitlement checks, a bounded native inventory query or controller-wide post-return authorization proof.

`php tests/index_viewer.php` executes the actual audit index, access/store/report libraries and audit template with synthetic SDK/request hooks and genuine private JSON/lock IO. It binds the original viewer across subscription selection, report/policy reads and final page preparation; rejects viewer switches, logout, role/impersonation changes and malformed IDs; and clears subscription/report/status/filter data and administrator controls on refusal. Stable admin/customer/impersonated views, same-ID SDK object replacement, numeric zero IDs and empty subscription views remain controlled. Cleared-template rendering contains no synthetic private canaries and retains the credit; the quiescent synthetic report/policy/queue/rate/bridge/rotation files and stream counts remain unchanged. Linux/Windows PHP CI runs these controls, not native Plesk session reload, error-page rendering, continuously atomic permission checks or export/refresh/open acceptance.

`php tests/release_authorization.php` executes unchanged release/store bodies with current SDK administrator snapshots, genuine private reads/locks/replacements and a supplied PHP transport fixture, never HTTP-supplied transport. Checks reject demotion, impersonation, logout, administrator switches and malformed identity at admission, transport, success/failure publication and cached GET. A rejected pre-admission request leaves the cooldown/cache unchanged; an admitted attempt is not refunded when later authorization fails, and prior result/failure metadata is preserved. Stable same-ID replacements and zero-valued IDs, passive no-network reads, unrelated quiescent private-state hashes, stream counts and lock recovery are controlled. The six-second HTTPS/64 KiB response limits, five-minute cooldown and manual-only native installation remain unchanged. This is SDK/transport/IO ordering coverage, not native session reload, actual TLS, atomic continuous revocation or real shared-server lifecycle proof.

## Remaining 1.0 Gates

Implemented in source with fixture tests: native service-plan hook/policy mapping, queue expiry/failure/identity protections and administrator release-discovery UI. Native role/synchronization/network/upgrade validation remains required.

Scheduled stale-cache rotation is now implemented in source and fixture-tested, opt-in and subject to existing caps. The isolated Linux container's SDK readback confirms one registered module rotator with scheduling disabled. This is not working background execution. Native execution, full idempotent upgrade/removal, active-worker uninstall guards and large-fleet inventory-query bounds still need native verification. No unattended installer is included.

`php tests/scheduler_deadline.php` runs the existing policy/rotation suites, then exercises the unchanged scheduler body with genuine private queue state and deterministic post-operation clocks. Its 224 controls cover claim, inventory, final report lookup, subscription relookup, reservation, task setup, manager construction and accepted-task return below/equal/above the ten-second monotonic deadline, plus failed starts. Expired work cannot begin a new task; late reservations release only their token and retain the consumed rate attempt. A task already accepted by Plesk retains its live reservation. Completion markers and stream cleanup remain intact. These SDK fixtures cannot interrupt a native database/filesystem/task call, certify native concurrency or prove a bounded inventory query.

Still open: native Windows/Linux panel QA, Windows ACL installer verification, native WHMCS connection/deployment/freshness, independent post-fix security review and final version-matched native tutorials. Pending features must not be advertised as available. See [platform matrix](platform-support.md).
